# AI QA Copilot

## Призначення

AI QA Copilot допомагає працювати з тестовою документацією, але не виконує систему й не встановлює PASS/FAIL. Об’єктивний статус API-тесту встановлює лише API Runner за реальною HTTP-відповіддю.

## Шари перевірки

1. Context Builder збирає обмежений за розміром контекст проєкту, Requirements, схожих тесткейсів, Test Suites, виконань і дефектів, доступних поточному користувачу.
2. Deterministic Reviewer перевіряє структуру, явні суперечності, формалізовані мінімальні довжини у Requirement, арифметику відсотків та можливі дублікати.
3. За наявності Ollama або зовнішньої моделі semantic review доповнює, але не замінює детерміновані докази. Відповіді без цитати з поля відхиляються.
4. Findings дедуплікуються. Якість тесткейсу розраховується прозоро: `100 − штрафи`, де CRITICAL=30, HIGH=15, MEDIUM=7, LOW=3.

## Контроль змін

Для finding із конкретним Before/After створюється `AIFixProposal`. Виправлення не застосовується автоматично. Перед застосуванням сервер порівнює `updated_at` тесткейсу зі знімком аналізу; якщо тест змінився, відповідь відхиляється і review потрібно повторити.

## Benchmark

Набір `qa-copilot-v1` містить некоректний expected result для невалідних даних, суперечність Requirement мінімальної довжини, пропущені передумови й результати кроків, коректний кейс та неоднозначний кейс без Requirement. Результат benchmark зберігається у `AIBenchmarkRun` і містить precision, recall, F1, false positives та false negatives. Це оцінка тільки детермінованих правил. Інтеграційна оцінка LLM не запускається, коли Ollama/зовнішній провайдер недоступні.
